# Лабораторная работа № 3. Типы данных, каррирование и ленивое вычисление

Всё решение находится в `user_loading.py`. Классы и функции определены в одном
файле; импортируются только инструменты стандартной библиотеки Python.
Нужен Python 3.10 или новее из-за конструкции `match/case`.

## Запуск

Из корневой папки проекта:

```powershell
python Лаба_3/user_loading.py
```

Ожидаемый вывод:

```text
Пользователи: [User(name='Egor', age=21, email='Egor@cos.ru'), User(name='Lada', age=20, email='Lada@sin.ru')]
```

## 1. Импорты

```python
from dataclasses import dataclass
from enum import Enum
from typing import Callable, Generic, TypeVar, Union
```

- `from` указывает модуль, из которого импортируется имя.
- `import` подключает перечисленные имена; запятые разделяют их.
- `dataclass` автоматически создаёт для класса конструктор, сравнение по полям
  и текстовое представление.
- `Enum` служит основой перечисления с фиксированными вариантами.
- `Callable` описывает тип функции или другого вызываемого объекта.
- `Generic` позволяет создать класс с параметром типа.
- `TypeVar` создаёт переменную типа.
- `Union` описывает объединение типов.

Импорта из другого решения или сторонних библиотек нет.

## 2. Переменные типов T и E

```python
T = TypeVar("T")
E = TypeVar("E")
```

`T` обозначает тип успешных данных, `E` — тип ошибки. Знак `=` связывает имя
с результатом вызова справа. `TypeVar(...)` создаёт переменную типа, круглые
скобки обозначают вызов, а строки `"T"` и `"E"` задают её имя.

В `Result[list[User], str]` вместо `T` используется `list[User]`, а вместо
`E` — `str`. Это описание типов, а не сами список или сообщение.
Аннотации не выполняют автоматическую проверку значений при запуске.

## 3. Тип-сумма LoadState

```python
class LoadState(Enum):
    LOADING = "loading"
    SUCCESS = "success"
    ERROR = "error"
```

`class` начинает определение класса. `LoadState` — имя, `(Enum)` — указание
базового класса. Двоеточие открывает тело класса, отступы обозначают его строки.

`LOADING`, `SUCCESS`, `ERROR` — имена вариантов; строки справа от `=` — их
значения. Они обозначают загрузку, успех и ошибку соответственно.
Одно значение выбирается из альтернатив: загрузка ИЛИ успех ИЛИ ошибка.
Поэтому перечисление представляет тип-сумму.

`LoadState` описан по заданию. В демонстрационном блоке нет настоящего UI
и переключения этих состояний. Отложенную загрузку запускают явным вызовом задачи.

## 4. Тип-произведение User

```python
@dataclass(frozen=True)
class User:
    name: str
    age: int
    email: str
```

`@` начинает запись декоратора, применяемого к следующему определению класса.
`dataclass(...)` получает настройку `frozen=True`: имя аргумента `frozen`,
знак `=` для передачи именованного аргумента, логическая константа `True`.
Здесь `=` не является отдельной инструкцией присваивания переменной.

`class User:` определяет класс пользователя. Записи `name: str`, `age: int`,
`email: str` описывают поля: имя, возраст и email. Двоеточие после имени поля
начинает аннотацию типа. `str` означает строку, `int` — целое число.

Один объект содержит имя И возраст И email, поэтому это тип-произведение.
Например, вызов `User("Egor", 21, "Egor@cos.ru")` создаёт объект, присваивая
значения полям в порядке их объявления. Конструктор создаётся декоратором.

`frozen=True` запрещает обычную замену полей после создания объекта.
Попытка `user.age = 22` приведёт к `FrozenInstanceError`.
Проверка возраста и формата email не входит в это поведение.

## 5. Варианты Success, Failure и объединение Result

```python
@dataclass(frozen=True)
class Success(Generic[T]):
    value: T


@dataclass(frozen=True)
class Failure(Generic[E]):
    error: E


Result = Union[Success[T], Failure[E]]
```

У обоих классов декоратор действует так же, как у `User`.

- `Success` — класс успешного результата. `(Generic[T])` указывает базовый класс
  с параметром типа `T`. Поле `value: T` хранит успешные данные.
- `Failure` — класс ошибки. `Generic[E]` задаёт параметр типа ошибки,
  а поле `error: E` хранит её описание.
- Квадратные скобки в этих записях передают параметры типов.
- `Result` — псевдоним объединения. `Union[...]` перечисляет альтернативы,
  разделённые запятой: `Success[T]` ИЛИ `Failure[E]`.

В этой работе успех содержит список пользователей, ошибка — строку:
`Success(users)` или `Failure("Список пользователей пуст")`.
Создание `Failure` не вызывает исключение: это обычное возвращаемое значение.

`frozen=True` не замораживает вложенные объекты. Список в `Success.value`
всё ещё допускает изменение, хотя обычное присваивание самому полю запрещено.

## 6. Источник пользователей

```python
def user_source() -> list[User]:
    return [
        User("Egor", 21, "Egor@cos.ru"),
        User("Lada", 20, "Lada@sin.ru"),
    ]
```

`def` определяет функцию, `user_source` — её имя. Пустые скобки в заголовке
означают отсутствие параметров. Стрелка `->` начинает аннотацию результата,
`list[User]` означает список пользователей. Двоеточие открывает тело функции.

`return` возвращает результат и завершает вызов. Квадратные скобки после него
создают список. `User(...)` вызывает класс, создавая пользователя. Запятые
внутри круглых скобок разделяют аргументы, снаружи — элементы списка.
Завершающая запятая после последнего элемента разрешена.

Кавычки ограничивают строки, числа `21` и `20` — целочисленные литералы.
Символы `@` и `.` внутри email являются обычными символами текста.

Определение функции не выполняет её тело. Каждый вызов `user_source()` создаёт
новый список и новые объекты пользователей. Имя `user_source` без скобок
обозначает саму функцию.

## 7. Каррированная функция load_users

```python
def load_users(error_message: str) -> Callable[
    [Callable[[], list[User]]], Callable[[], Result[list[User], str]]
]:
```

Функция принимает один параметр `error_message` типа `str`.
Она возвращает функцию, которая примет источник и вернёт отложенную задачу.

Общий вид `Callable`: `Callable[[типы_аргументов], тип_результата]`.

| Аннотация | Значение |
| --- | --- |
| `Callable[[], list[User]]` | Источник без аргументов, возвращающий список пользователей. |
| `Callable[[], Result[list[User], str]]` | Задача без аргументов, возвращающая результат. |

Внешний `Callable` устроен как `Callable[[тип_источника], тип_задачи]`.
Внешний список типов аргументов содержит один элемент — тип функции-источника.
Запятая после этого списка отделяет тип возвращаемой задачи.
Пустые `[]` внутри описания источника и задачи означают отсутствие аргументов.
Финальные `]` и `:` закрывают аннотацию и открывают тело `load_users`.
Переносы строк внутри скобок разрешены и служат для удобства чтения.

Каррирование означает, что несколько аргументов задаются последовательными
вызовами функций по одному аргументу:

```python
load_users("Список пользователей пуст")(user_source)
```

Сначала передаётся сообщение, затем источник. Результат этих двух вызовов —
функция-задача. Её последующий вызов без аргументов запускает загрузку.

## 8. Вложенная функция with_source

```python
    def with_source(
        source: Callable[[], list[User]],
    ) -> Callable[[], Result[list[User], str]]:
```

Отступ из четырёх пробелов показывает, что определение находится внутри
`load_users`. `source` — параметр, содержащий функцию-источник.
Его тип описан через `Callable`. Завершающая запятая в списке параметров допустима.
Результат `with_source` — функция без аргументов, возвращающая `Result`.

Вызов `with_source` ещё не вызывает источник. Он создаёт и возвращает `run`.

## 9. Отложенная функция run и замыкание

```python
        def run() -> Result[list[User], str]:
            users = source()
            return Success(users) if users else Failure(error_message)
```

Определение `run` с отступом в восемь пробелов вложено в `with_source`.
У неё нет аргументов; результат — `Success` со списком или `Failure` со строкой.

Внутри `run` отступ уже двенадцать пробелов. Строка `users = source()`
вызывает источник и сохраняет список в локальную переменную `users`.
Именно здесь происходит фактическое получение данных.

`return Success(users) if users else Failure(error_message)` — возврат
условного выражения, также называемого тернарным оператором:

1. Сначала проверяется `users`: пустой список ложен, непустой истинен.
2. Для непустого списка создаётся и возвращается `Success(users)`.
3. Для пустого создаётся и возвращается `Failure(error_message)`.
4. Выполняется только выбранная ветка.

`source` берётся из параметров `with_source`, `error_message` — из параметров
`load_users`. Функция с сохранённым доступом к переменным внешних функций
называется замыканием. Благодаря этому `run` может использовать эти значения
после завершения внешних вызовов. Глубокие копии объектов при этом не создаются.

```python
        return run

    return with_source
```

Отступы определяют принадлежность возвратов: `return run` находится
в `with_source`, `return with_source` — в `load_users`.
Обе строки возвращают функции. Скобок после имён нет, поэтому тела возвращаемых
функций в этих строках не выполняются.

`return run` возвращает функцию на будущее; `return run()` выполнил бы её
немедленно и вернул результат. В решении используется первый вариант.

## 10. Подготовка и выполнение

```python
if __name__ == "__main__":
    prepare_load = load_users("Список пользователей пуст")
    task = prepare_load(user_source)
    result = task()
```

`if` начинает условную инструкцию. `__name__` — специальная переменная Python,
`==` — оператор сравнения на равенство, `"__main__"` — имя главного запускаемого
модуля. Блок выполняется при прямом запуске и пропускается при обычном импорте.

1. В `prepare_load` сохраняется возвращённая функция `with_source`.
   Сообщение уже задано, источник ещё не задан.
2. В `task` сохраняется функция `run` с выбранным источником.
   `user_source` передаётся без скобок и не вызывается.
3. `task()` вызывает `run`. Только теперь создаётся список, проверяется пустота
   и получается объект `Success` или `Failure`, сохраняемый в `result`.

Каррирование относится к поочерёдной передаче сообщения и источника.
Ленивое вычисление относится к выполнению подготовленной задачи по запросу.
Отложенная функция без аргументов также называется thunk.

Полная цепочка одной строкой:

```python
result = load_users("Список пользователей пуст")(user_source)()
```

Это обычное синхронное выполнение по запросу, а не фоновая или асинхронная работа.
Кеширования нет: каждый вызов одной задачи повторно вызывает источник.

## 11. Обработка результата

```python
    match result:
        case Success(value):
            print("Пользователи:", value)
        case Failure(error):
            print("Ошибка:", error)
```

`match` начинает структурное сопоставление, `result` — исследуемый объект.
Каждый `case` задаёт образец. `match` и `case` — мягкие ключевые слова Python.

- `Success(value)` в `case` — образец класса, а не создание объекта.
  Он распознаёт успех и связывает имя `value` с содержимым одноимённого поля.
- `Failure(error)` аналогично извлекает сообщение ошибки.
- Позиционное извлечение поддерживается атрибутом `__match_args__`,
  автоматически создаваемым `dataclass`.
- `print` выводит строку-подпись и полученные данные, разделяя их пробелом.
  Двоеточие внутри строки — обычный символ текста.
- Выполняется первый подходящий образец.

Для проверки ошибки можно временно заменить создание задачи в блоке запуска на:

```python
task = prepare_load(lambda: [])
```

`lambda: []` создаёт анонимную функцию без аргументов, возвращающую пустой список
при вызове. После `result = task()` программа выведет:

```text
Ошибка: Список пользователей пуст
```

## 12. Названия операторов и синтаксических конструкций

| Запись | Название и назначение |
| --- | --- |
| `=` в присваивании | Знак присваивания; связывает имя с результатом выражения. |
| `=` в `frozen=True` | Передача именованного аргумента. |
| `==` | Оператор сравнения на равенство. |
| `A if условие else B` | Условное выражение, или тернарный оператор. |
| `if ...:` | Условная инструкция. |
| `from ... import ...` | Инструкция импорта. |
| `class` | Определение класса. |
| `def` | Определение функции. |
| `return` | Инструкция возврата. |
| `match/case` | Структурное сопоставление с образцом. |
| `@dataclass(...)` | Применение декоратора. |
| `(...)` | Параметры определения, аргументы вызова, базовые классы или образцы полей — в зависимости от контекста. |
| `[...]` | Создание списка либо параметризация типа — в зависимости от контекста. |
| `:` | Начало блока или аннотации типа. |
| `->` | Начало аннотации возвращаемого типа. |
| `,` | Разделитель элементов, аргументов и типов. |
| `True` | Логическая константа «истина». |
| `"..."` | Строковый литерал. |
| `21`, `20` | Целочисленные литералы. |

Отступы задают вложенность блоков. Пустые строки служат для удобства чтения.
`_` внутри обычного имени соединяет части имени, а в `__name__` подчёркивания
являются частью специального имени. Не каждый знак в таблице является оператором:
например, `->` — разделитель аннотации, а `return` — инструкция.

## 13. Мощность типов и побочные эффекты

У `LoadState` три значения:

```text
|LoadState| = 1 + 1 + 1 = 3
```

`User` — произведение трёх полей:

```text
|User| = |str| × |int| × |str|
```

У `Result[list[User], str]` два варианта, но не два значения:

```text
|Result[list[User], str]| = |list[User]| + |str|
```

В математической модели без ограничения памяти строки и целые числа образуют
счётно бесконечные множества. Пользователей и конечных списков пользователей
произвольной длины также счётно бесконечно много. Поэтому мощность результата
равна `ℵ₀ + ℵ₀ = ℵ₀`: счётная бесконечность.

Текущий `user_source` создаёт новые объекты без внешних побочных эффектов.
Повторное выполнение задачи даёт равные по содержимому результаты.
Вывод через `print` — побочный эффект демонстрационного блока.
Если передать другой источник, свойства задачи будут зависеть от него:
сеть и файлы дадут соответствующие эффекты при выполнении, а выброшенное
исключение распространится из `task()`. В `Failure` здесь преобразуется
только пустой список.
